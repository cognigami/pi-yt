# pi-yt Phase 2 Implementation Plan

## Source Design and Phase Decision

Canonical Phase 1 design source: `pi-yt/docs/pi-yt-design.md`.

The next step is **Phase 2 planning**. The supplied design explicitly captures an accepted Phase 1 boundary for handoff into implementation planning: package name `pi-yt`, MVP tool `yt_transcript`, transcript/subtitle scope only, no raw `yt-dlp` passthrough, and screenshot/frame extraction deferred.

## Planning Assumptions

Unless the operator overrides these before implementation:

- Support any `http:` or `https:` URL accepted by `yt-dlp`, with YouTube as the primary test target.
- Disable playlist expansion for the MVP; one tool call should process one video resource.
- Default language list is `["en"]`.
- Default subtitle source preference is `manual_then_auto`.
- Auto-generated subtitles are allowed by default after manual subtitles.
- Transcript text includes timestamps by default.
- Browser-cookie and authenticated-video support are out of scope for the first release.
- `yt-dlp` is an external executable dependency expected on `PATH`; the tool should fail clearly if unavailable.
- The existing `pi-yt` scaffold may be incomplete; repair setup by copying/adapting files from sibling Pi extension packages and linking local dependencies as needed.
- Do not run `bun` merely to initialize or repair the scaffold; use file operations only for setup.

### WP2 — Public tool contract

File targets:

- `pi-yt/src/index.ts`
- `pi-yt/src/tools/yt-transcript.ts`
- `pi-yt/src/ytdlp/contracts.ts`
- `pi-yt/src/index.test.ts`
- `pi-yt/src/tools/yt-transcript.test.ts`

Scope:

- Register one tool named `yt_transcript` with label `yt-transcript`.
- Use a strict schema for URL, languages, source preference, timestamp preference, and timeout.
- Add prompt metadata that tells the LLM to use `yt_transcript` for video transcript extraction instead of shelling out to `yt-dlp`.
- Reject unsupported URL schemes and malformed inputs before invoking `yt-dlp`.
- Keep raw arbitrary `yt-dlp` arguments out of the schema.

Acceptance assertions:

- `PYT-P2-A4`: Tool registration exposes exactly the MVP transcript tool and no generic CLI passthrough.
- `PYT-P2-A5`: Tool schema reflects the Phase 1 input contract and defaults.
- `PYT-P2-A6`: Invalid URL schemes are rejected without executing external commands.

### WP3 — Fixed `yt-dlp` execution boundary

File targets:

- `pi-yt/src/ytdlp/execute.ts`
- `pi-yt/src/ytdlp/contracts.ts`
- `pi-yt/src/ytdlp/execute.test.ts`

Scope:

- Encapsulate all `yt-dlp` subprocess interaction behind a small typed function.
- Use fixed safe arguments for metadata/subtitle discovery and subtitle retrieval.
- Enforce one-resource behavior and avoid playlist traversal.
- Run inside a temporary or staged working directory, not the caller's project directory.
- Apply timeout and cancellation handling.
- Convert common failure modes into clear operator-facing errors: executable missing, unsupported URL, no subtitles, network/access failure, timeout.

Acceptance assertions:

- `PYT-P2-A7`: The execution layer never accepts raw model-provided CLI arguments.
- `PYT-P2-A8`: Playlist expansion is disabled for MVP calls.
- `PYT-P2-A9`: Missing `yt-dlp` produces a clear actionable error.
- `PYT-P2-A10`: Timeout and non-zero exits are surfaced without silent fallback media downloads.

## Risks and Review Gates

### Risks

- `yt-dlp` output filenames and subtitle formats may vary by extractor.
- Auto-generated subtitles may include duplicated or fragmented captions requiring normalization.
- Live video sites can change behavior, so deterministic tests must rely on fixtures/mocks.
- Accidentally exposing raw args or playlist downloads would widen the safety boundary.
- Transcript content can be large, so truncation and artifact staging are mandatory.

### Required review gates

- Contract review after WP2: confirm schema, defaults, and no raw argument passthrough.
- Safety review after WP3: confirm fixed args, URL validation, timeout behavior, no playlist traversal, and no media-download fallback.
- Artifact review after WP5: confirm staged outputs, truncation behavior, and details shape.
- Final review after WP7: confirm README, tests, and optional smoke-test notes.

## Out-of-Scope Follow-ups

Potential future work after MVP acceptance:

- `yt_metadata` for metadata/subtitle-language discovery without transcript extraction.
- `yt_frame` for screenshots/frame extraction with explicit `ffmpeg` dependency.
- Configurable language fallback policy.
- Optional trusted cookie/browser-auth support behind explicit operator configuration.
- Optional transcript cache keyed by video ID, language, and subtitle source.
